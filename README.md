# SlipNote

把一张手写纸条，放到对方的手机桌面上。

配对之后，你写一张纸条发出去，对方的桌面小部件几秒内就变成这张纸。
不用点开 App，划到桌面就能看见。

## 能做什么

**写**

- 手写画板，五种笔宽、六种颜色，笔画有粗细变化
- 双指放大，方便写小字
- 垫一张图照着描
- 贴贴纸：从相册抠图，贴在纸上一起发出去

**收**

- 桌面小部件直接显示，收到就更新
- 收到的纸条自动存进收件箱
- 喜欢的可以收藏
- 别人贴的贴纸，能单独取下来收进自己的贴纸库，再贴到别的纸条上

**多人**

- 一个账号可以配多个好友
- 群组接力：A 传给 B，B 传给 C
- 群组随机：随机传给群里一个人，双方互相不知道是谁

## 装起来

需要一台能跑 Node.js 的服务器，和一个 Android 手机。

### 服务端

```bash
cd server
npm install
npm start
```

默认监听 `8080`。换端口和数据目录：

```bash
PORT=9000 DATA_DIR=/var/lib/slipnote npm start
```

想放到服务器上长期跑，`server/deploy/` 里有 systemd 和 nginx 的配置可以直接用。

### Android

```bash
cd android
./gradlew assembleDebug
```

需要 JDK 17 和 Android SDK。

**装之前改一行**：`android/app/src/main/java/com/notedrop/demo/net/AppConfig.kt`
里的 `DEFAULT_SERVER`，换成你自己的服务器地址。也可以先装再用 App 里的
「连接设置」填，效果一样。

## 测一下

```bash
cd server
node test/run-local.mjs test/e2e.js test/groups.js test/auth.js test/stickers.js test/ack.mjs
```

会自己起一个临时服务端，用独立的端口和数据目录，不碰你的正式数据。

覆盖的内容：配对发纸条、群组接力、随机匿名投递、账号登录、贴纸传输、
离线消息补发、重复投递和越权确认。

## 目录

```
android/   安卓 App 和桌面小部件（Kotlin）
server/    Node.js 服务端（Express + SQLite）
```

两边可以分开用。服务端就是个普通的 HTTP API，App 里能填任意服务器地址。

## 一些实现上的选择

**为什么不接厂商推送**

小米、华为、OPPO、vivo 四套 SDK 都要接一遍，成本不低。自用或者小范围用的话，
长连接更快也更省事，所以用了 WebSocket。

**消息不会丢**

服务端不主动标记「已送达」，要等客户端确认收到才算数。没确认的会一直
留在队列里，下次连上接着发。

另外客户端每 60 秒会主动拉一次。手机在后台时，长连接经常被系统悄悄掐掉，
两边都察觉不到，光靠长连接会出现消息延迟很久的情况。

**抠图用颜色键，没用 AI**

一开始试过 MediaPipe，但那是语义分割模型，只认识二十来种常见物体。
拿商品图或者截图给它，结果基本是随机的。

现在改成类似 Photoshop 魔棒的做法：点哪里，就去掉哪里颜色相近的一片。
白底图、截图、手写字用起来几乎不出错，还能撤销、能调容差。

**画布尺寸是固定的**

编辑页的工具栏是个能收起来的抽屉。如果画布跟着工具栏的高度变，
抽屉一开一合，写好的内容会被裁掉、贴纸会跑位。

所以画布在第一次打开时就定死尺寸，界面只是看它的窗口。
导出永远是完整一张。

## 已知问题

- 只做了安卓，iOS 没做
- 主要在小米手机上测过，其他品牌的桌面小部件没逐个验证
- App 被系统彻底杀掉后收不到实时通知，要等下次打开
- 服务端是单进程加 SQLite，适合自己用，不适合大量用户
