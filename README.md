# 小纸条（NoteDrop）

把一张手写纸条放到对方的手机桌面上。

两个人（或一个群组）配对之后，你可以打字、手写涂鸦、贴贴纸，
点发送 —— 对方的**桌面小部件几秒内就会变成这张纸条**。

```
写纸条  →  发送  →  对方桌面小部件立刻更新
                    （不用点开 App 就能看见）
```

## 这个仓库里有什么

| 目录 | 内容 |
| --- | --- |
| [`android/`](android/) | Android App + 桌面小部件（Kotlin，View 体系） |
| [`server/`](server/) | 服务端：注册、配对、群组、纸条中转 + WebSocket 实时推送（Node.js） |

两部分可以独立使用：服务端能单独跑起来当 API 用，
App 的「连接设置」里可以填任意服务器地址。

## 功能

**桌面上那一张**

- 桌面小部件直接显示收到的纸条，**不需要点开 App**
- 收到即刷新，不依赖系统那 30 分钟的定时器
- 小尺寸只显示文字，大尺寸才铺开手写画面
- 纸张三种：白纸 / 方格纸 / 米黄

**写的那一张**

- 手写画板：五种笔宽、六种颜色、速度感应笔锋、橡皮
- 双指缩放做精细书写（画布尺寸不变，导出永远是完整一张）
- 工具抽屉可拖拽，收起时只剩一根把手，把屏幕让给画板
- **描画**：垫一张参考图，调透明度后照着描；这层不会发出去
- **贴纸**：从相册抠图 → 贴在纸上 → 随纸条发送；
  对方能把贴纸**单独取下来**收进自己的贴纸库，再贴到别的纸条上

**收到之后**

- 收件箱：所有收到的纸条自动存档（桌面只显示最新那张）
- 收藏夹：主动收藏的纸条，独立存储不受清理影响
- 详情页能完整查看，点贴纸可「取下」或「再贴到新纸条上」

**多人玩法**

- 一对多配对：一个账号可以和多个好友配对
- 群组接力：A→B→C→D 依次传下去
- 群组随机：随机匹配群内一人，**双方身份互相不可见**

**账号**

- 账号密码登录，账号（username）不可变、昵称随便改
- 改昵称不会丢配对 —— 配对绑的是账号不是名字

## 技术上的几个选择

**为什么用 WebSocket 而不是厂商推送**

接入小米 / 华为 / OPPO / vivo 四套推送 SDK 的成本很高，
而自用或小范围使用时，长连接反而实时性更好、更省事。
代价是需要在客户端做兜底轮询（见下）。

**消息不丢：ACK 机制**

服务端把纸条标记为「已送达」之前，会等客户端处理完并回执。
没有回执的纸条会一直留在待发队列里，下次拉取还发。

这一点是有教训的：早期版本服务端一边返回一边标记已送达，
而客户端只取了返回列表的**最后一张**，导致对方连发三张时
有两张被永久丢失 —— 服务端以为送出去了，客户端根本没收到。

客户端每 60 秒还会主动拉一次待收纸条。长连接在国内手机上
很容易被系统静默掐断（省电策略、切网络），那种断开两边都没有感知，
只靠长连接必然出现「一条消息延迟几十分钟」的情况。

**抠图为什么用颜色键而不是 AI 模型**

最早用 MediaPipe 的 `deeplab_v3` 做自动抠图。那是**语义分割**模型，
只认识 PASCAL VOC 的 20 类常见物体，输出的是「这块像素属于哪一类」，
不是「哪块是主体」。拿普通照片或截图给它，结果基本是随机的。

现在换成**颜色键（魔棒）**：用户点哪儿，就去掉哪儿颜色相近的连通区域。
不需要认识任何东西，所以白底图、截图、手写字几乎百发百中，
而且结果确定、可撤销、容差可调。

**画布尺寸是固定的**

编辑页的工具栏是个可拖拽抽屉，展开时画布区会变矮。
如果画布尺寸跟着控件走，抽屉一开合，笔迹会被裁、贴纸位置会漂。

所以画布尺寸在第一次布局时定死，界面只是一个观察窗口 ——
窗口可大可小，纸始终是那张纸。导出永远是整张画布。

## 跑起来

### 服务端

```bash
cd server
npm install
npm start          # 默认 0.0.0.0:8080
```

环境变量：

```bash
PORT=9000 DATA_DIR=/var/lib/notedrop npm start
```

跑测试（会自己起一个临时服务端，用独立端口和临时数据目录）：

```bash
node test/run-local.mjs test/e2e.js test/groups.js test/auth.js test/stickers.js test/ack.mjs
```

部署到服务器见 [`server/deploy/`](server/deploy/)，
里面有 systemd unit 和 nginx 反代配置。

### Android

```bash
cd android
./gradlew assembleDebug
```

需要 JDK 17、Android SDK（compileSdk 36）。
SDK 路径依次从 `local.properties`、`ANDROID_HOME`、`ANDROID_SDK_ROOT` 找。

**装之前先改服务器地址**：`app/src/main/java/com/notedrop/demo/net/AppConfig.kt`
里的 `DEFAULT_SERVER`。也可以在 App 的「连接设置」页里手填，
填过的值会存本地并优先生效。

## 测试覆盖

服务端有五套集成测试，都是**真实网络往返**（起临时服务端 + 真 WebSocket），
不是 mock：

| 测试 | 覆盖 |
| --- | --- |
| `e2e.js` | 配对 → 发纸条 → 秒收的完整链路，含涂鸦/纸张/方向透传 |
| `groups.js` | 群组接力、匿名随机投递、非成员拒绝、单人群拒绝 |
| `auth.js` | 注册登录、改昵称不丢配对、旧 token 失效、防用户名枚举 |
| `stickers.js` | 贴纸透传、非法数值钳制、未知字段丢弃、数量上限、离线补发 |
| `ack.mjs` | 离线多张不丢、未 ACK 重复投递、越权 ACK 被拒 |

## 已知限制

- **iOS 没做**。桌面小部件那部分在 iOS 上要换一套 WidgetKit 实现。
- **只适配了 Android**。目前主要在小米上实测；其他厂商的桌面
  （华为 / OPPO / vivo / 鸿蒙）小部件行为有差异，没逐个验证过。
- **没有厂商推送**。App 被彻底杀掉后收不到实时通知，
  要等下次打开 App 或系统拉起前台服务。
- **前端是原型级别**。`server/public/proto.html` 是设计用的 HTML 原型，
  不是生产前端。
- 服务端是单进程 + SQLite，适合自用和小范围，不适合大规模。
